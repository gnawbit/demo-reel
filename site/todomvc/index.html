TabRetake / TodoMVC walkthrough

A README GIF and portrait demo from a TodoMVC story

Add two tasks, complete the first, filter completed items, then return to the full list. Keep the steps as JSON and change the task text when you need a fresh walkthrough.

This maintainer-run recipe uses the unmodified TodoMVC JavaScript ES6 implementation with fictional tasks. It is a reproducible example, not an upstream adoption claim.

Download the story

1. Install the CLI

Use Node.js 20.9+ and Git on Windows, macOS or Linux. FFmpeg and ffprobe are included.

npm install --global @gnawbit/tabretake@0.4.2
tabretake setup
tabretake doctor --json

On Linux, use tabretake setup --with-deps if Chromium system libraries are missing. To let an Agent author other flows, see Skill installation.

2. Serve the pinned app

The upstream repository includes a static build, so this example needs no application build or account.

git clone --filter=blob:none --sparse https://github.com/tastejs/todomvc.git demo-todomvc
git -C demo-todomvc fetch --depth 1 origin ff43b02e59dfa604386bb382034b2cd07c2bcd8a
git -C demo-todomvc checkout --detach ff43b02e59dfa604386bb382034b2cd07c2bcd8a
git -C demo-todomvc sparse-checkout set examples/javascript-es6

Start the server in one terminal. Replace the placeholder with your checkout's absolute path; serve --dir resolves relative paths from the CLI installation.

tabretake serve --dir "<absolute path to demo-todomvc/examples/javascript-es6/dist>" --port 4187

The story uses http://127.0.0.1:4187/. If that port is occupied, change both the server port and the story's url.

3. Record and render

Save the download as todomvc-story.json in your working directory. In a second terminal:

tabretake validate --config todomvc-story.json --json
tabretake record --config todomvc-story.json --out demo-todomvc-output --json
tabretake render --config demo-todomvc-output/record.json --vertical --zoom 1 --json

The render returns paths to landscape and portrait MP4s, GIFs and PNG posters. The recording also saves screenshots of the added, completed, filtered and final states.

4. Edit and repeat

Change only the second task's value from Record walkthrough to Publish walkthrough. Repeat the record and render commands, using demo-todomvc-updated for the output directory and its record.json.

For appearance changes, such as captions or branding, edit the saved timeline and render it again. Changed task data or clicks require a new recording.

Verified on Windows with demo-reel v0.3.3 on 2026-11-23: two runs produced approximately 12.7-second videos after correcting the overlapping filter label. To reproduce that version, change #main to #v0.3.3 in the install command, run the steps with demo-reel, and use the original story. Both runs passed complete media decoding and sampled-frame checks. An Agent followed the public instructions from a supplied project link; this does not measure automatic discovery.

What the story assumes

  • The pinned app starts with empty in-memory data in each new recording context. Its generated item IDs and filter selectors are specific to this implementation.
  • The story uses a 640×560 viewport and disables click zoom to keep the list visible. The landscape frame crops the top title and captions cover some footer help text; the tasks and filters remain visible. Inspect the result at your intended display size.
  • The Completed filter uses .filters a[href='#/completed']. In v0.3.3, a partial text: "Completed" match can click the Clear completed button instead. Check the expected result after actions.
  • Output is silent. This example does not need login state or external services.
